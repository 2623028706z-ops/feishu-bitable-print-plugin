# 标签打印方向与缩放修复规格

## 目标

彻底消除标签打印的方向歧义和二次缩放。标签设计尺寸、内容方向和标签机进纸方向必须是独立概念；横竖切换不得破坏用户保存的字段位置、尺寸或字体。

## 技术栈与命令

- React 18.3、TypeScript 5.7、Vite 6、react-to-print 3.3。
- 单测：`npm test -- --run`
- 构建：`npm run build`
- 打印验收：Chrome Print-to-PDF + `pdfinfo`，检查 PDF MediaBox 与内容边界。

## 行为约定

1. 标签宽高是设计纸张尺寸。例如 50×30mm 表示横向设计。
2. 普通模式发送与设计相同的物理页面，50×30mm 始终输出 50×30mm。
3. 纵向进纸适配模式只在打印阶段交换物理页面，并把完整设计卡片旋转铺满；不得缩放卡片内容。旧版旋转配置不迁移，首次升级按标签宽高输出。
4. 横竖切换按 X/Y 两个轴分别换算字段矩形，往返后恢复原值，字体大小保持不变。
5. 旧版已经裁窄的默认布局可恢复；无法可靠判断的用户自定义布局不得静默覆盖。
6. A4 加工单打印不受本次修改影响。

## 交互约定

- 保留“标签方向：横向 / 纵向”。
- 将模糊的 0°/90°/180°/270° 改为“标签机进纸：横向进纸 / 纵向进纸”，只暴露现场需要的两种模式。
- 预览工具栏显示实际发送给打印机的纸张尺寸。
- 提供“恢复默认排版”，用于修复旧版已缩小布局，不自动清除用户自定义内容。

## 测试策略

- 单元测试覆盖普通/纵向进纸、横向/纵向标签，以及旧旋转配置归零迁移。
- 模板测试覆盖任意尺寸横竖往返、元素边界、字体大小不变。
- 浏览器检查打印 iframe 的 `@page`、sheet、card 计算尺寸。
- PDF 检查页面宽高和内容外框，不接受仅验证 CSS 字符串。

## 边界

- 不新增依赖，不修改飞书数据读取和 A4 加工单。
- 不承诺 Web API 修改系统打印机驱动设置。
- 不覆盖 `src/lib/feishu-adapter.ts` 的现有用户改动。

## 完成标准

- 50×30 横向进纸输出 50×30 PDF，内容 1:1 铺满。
- 50×30 纵向进纸输出 30×50 PDF，50×30 内容旋转后 1:1 铺满。
- 横竖切换往返后字段矩形和字号与切换前一致。
- 线上构建包含新规则，并通过实际浏览器打印 iframe 与 PDF 验收。
