# 加工单分页与品类筛选规格

## 目标

让花众销售订单打印插件稳定完成两件事：

1. A4 加工单按物理页面显式分页，长内容不截断，每页都能独立识别客户、出货日期、表头和页码。
2. 从“成品档案表”的单选字段“品类”回填销售订单，品类筛选有值、可诊断、不会误把飞书记录 ID 当作显示文字。

目标用户是花众生产和出货人员。界面保持轻量生产工具风格：天蓝色作为操作强调色，筛选、模板编辑和打印状态分区清楚，不堆叠重复信息。

## 已确认数据规则

- 订单来源：花众销售订单汇总表当前视图或当前选择。
- 品类来源表：成品档案表。
- 品类字段名：品类。
- 品类字段类型：单选。
- 标签不打印 BOM；本规格的 BOM 配方只服务加工单。
- 加工单保留六列：花束、花材、加工扎数、单束用量、总支数、备注。
- 不创建配置表或共享表；模板继续保存在插件内。

## 关联策略

每条订单按以下顺序解析品类，第一项得到有效单选文字后停止：

1. 销售订单本身存在可显示的品类值时直接使用。
2. 读取销售订单的成品关联记录，并从关联的“成品档案表”记录读取“品类”。
3. 关联值缺失或不完整时，优先用花束编码匹配成品档案记录。
4. 编码仍无法匹配时，使用标准化后的花束名称匹配。

成品档案表整表批量加载一次并建立索引，不允许为每条销售订单重复请求。编码精确匹配优先；名称匹配出现多个候选时不随机选择，保留为空并返回明确诊断。

### 单选值解析

- 保留飞书字段完整元数据，至少包括字段 ID、名称、类型和关联目标表；不能再只压缩成 `名称 -> ID`。
- 字段名精确匹配优先；只有唯一候选时才允许规范化或模糊匹配。
- 单选显示文字优先读取 `value`、`displayValue`、`text`，再读取选项对象的 `name` 或 `label`。
- `recordId`、`recordIds`、字段 ID、选项 ID 只用于关联或诊断，不能作为品类名称。
- 销售订单的首选品类字段为空时，应继续尝试其他明确别名字段，而不是提前返回空值。
- 如果发现多个同名或近似“品类”字段，返回候选字段名称和类型，界面显示“未能确定品类字段”，不静默选错。

## 加工单分页规则

加工单不依赖浏览器自动拆分一张超长表，而是在渲染前计算出独立 A4 页面数组。

每页固定包含：

- 加工单标题
- 客户名称
- 出货日期；区间筛选显示明确的起止日期
- 当前页码和总页数
- 六列表头
- 本页配方行

分页规则：

1. 根据 A4 方向、页边距、标题区、表头、字体、行高和单元格内边距计算可用内容高度。
2. 文本按实际列宽换行后估算或测量行高，不能靠固定行数硬切。
3. 一个花束能完整放入下一页时，整组移到下一页。
4. 单个花束配方本身超过一页时允许拆分；续页首行重复花束名称并标记“续”。
5. 长花材名和备注自然换行，不缩小字号、不省略、不裁切。
6. 每个页面都是固定 A4 尺寸的独立节点，页面之间强制分页。
7. 页眉、表头和页码由每页真实渲染，不依赖 `<thead>` 自动重复或 CSS 计数器。
8. 打印区域禁止用 `transform` 移动页眉、表格或页脚；编辑偏移只影响预览编辑逻辑，不破坏打印分页。

## 精简规则

删除以下重复内容：

- “花众生产打印”小标题
- 右上角扎数、款数、订单数统计
- 底部解释文字
- 与客户、出货日期重复的装饰信息

保留标题、客户、日期、页码和六列表格。客户名称字号可以独立设置，并在每页重复。

## 插件内交互

- 加工单编辑区分成“常用”和“高级”：常用显示方向、页边距、字体、字号、客户字号、列宽；颜色、边框、偏移等进入折叠区。
- 打印前显示：设计纸型、实际输出纸型、横竖方向和页数。
- 明确提示浏览器打印框仍可能要求用户选择正确纸张和缩放比例；网页无法强制修改系统打印机驱动设置。
- 品类筛选项来自所有已加载订单的回填结果，而不是只读取销售订单当前记录中的品类字段。
- 品类加载失败时在筛选区显示原因：未找到成品档案表、未找到单选品类字段、关联歧义或记录未匹配。
- 无诊断问题时不显示技术性提示，保持界面简洁。

## 技术栈与命令

- React 18.3、TypeScript 5.7、Vite 6、Semi UI 2.102、飞书多维表格 JS SDK 1.0.2。
- 单元测试：`npm test -- --run`
- 构建：`npm run build`
- 本地预览：`npm run dev`
- 打印验收：Chrome 打印为 PDF，再用 `pdfinfo` 检查 A4 MediaBox、页数和方向。

## 项目结构

- `src/lib/feishu-adapter.ts`：飞书字段元数据、成品档案读取、订单品类回填和诊断。
- `src/lib/feishu-adapter.test.ts`：关联表、单选包装值、歧义和回退测试。
- `src/features/print/WorkOrderPrintDocument.tsx`：分页模型、每页 A4 文档和模板归一化。
- `src/features/print/WorkOrderPrintDocument.test.tsx` 或同目录测试：分页边界、续页、重复页眉和末行测试。
- `src/App.tsx`：筛选选项、诊断提示和打印状态展示。
- `src/styles.css`：屏幕预览与打印媒体样式。

## 代码约定

解析函数返回明确结果，不用空字符串同时表达“没有值”和“发生错误”：

```ts
type CategoryResolution = {
  value: string;
  source: 'sales' | 'linked-product' | 'product-code' | 'product-name' | 'none';
  issue?: 'table-missing' | 'field-missing' | 'field-ambiguous' | 'product-unmatched';
};
```

分页模型先生成纯数据，再由 React 渲染，避免把分页判断散落在 JSX 和 CSS 中。

## 测试策略

### 品类

- 成品档案表的“品类”是单选对象、包装数组和直接文字时都能得到显示文字。
- 订单关联记录可直接回填品类。
- 只有编码时能批量索引匹配；编码优先于名称。
- 空的首选品类字段会继续读取有效别名字段。
- 只有 `recordIds` 的查找值不会显示为品类。
- 多个近似品类字段、重名成品或无匹配记录会返回对应诊断。
- 成品档案只加载一次，不随订单数量发起 N 次请求。

### 加工单

- 单页边界前后各一组数据，验证不会丢失最后一行。
- 花束组可完整放下时不拆分；放不下时整体移到下一页。
- 超长单花束跨页时显示“花束名（续）”。
- 每一页都存在客户、出货日期、六列表头和 `当前页/总页数`。
- 超长花材名和备注换行后页数增加，文本内容保持完整。
- 横向和纵向 A4 均生成正确尺寸，无溢出页面的元素。
- PDF 文本提取验证首条、跨页条目和最后一条均存在。

## 边界

- 始终：保留真实飞书数据链路；先写测试再修复；构建后做真实浏览器和 PDF 验收。
- 先询问：新增依赖、改变飞书表结构、写入或创建多维表格记录、修改部署或登录配置。
- 禁止：创建配置表、把模板写回业务表、覆盖现有用户修改、声称网页能控制系统打印机设置。
- 本轮不修改标签 BOM 内容和标签几何规则。

## 完成标准

1. 销售订单本身没有品类字段时，插件仍能从“成品档案表”的单选“品类”生成筛选项并正确筛选。
2. 同一批订单读取成品档案的请求次数不随订单数增长。
3. 品类字段或关联发生歧义时，插件显示可操作的诊断，不显示错误值。
4. 任意长度加工单不丢首行、末行和跨页内容。
5. 每页重复客户、出货日期、六列表头和页码。
6. A4 横向和纵向 PDF 的物理尺寸、页数和内容完整性通过自动检查与人工预览。
7. `npm test -- --run` 与 `npm run build` 通过，线上构建完成浏览器打印烟测后才报告已完成。
